How it works

Three layers invisible to users, critical for the business

Every message sent on the platform goes through a security and intelligence pipeline before reaching the model.

01

Tyna Shield intercepts

PII, secrets, and prompt injection are masked before any transmission to the model. Protection is deterministic — it does not rely on probabilistic LLM classification.

Tyna Shield

Security that runs on every message, not optional

Shield is not an output filter. It's a layer that operates before sending to the model, deterministically and auditably.

PII

Personal data masking

SSN, business ID, email, credit card — detected and masked by deterministic regex. Zero probability of leakage of these fields.

Secrets

Secret and token blocking

AWS keys, GitHub and Slack tokens, JWTs — if detected, the entire message is blocked before any external transmission.

Prompt Injection

Prompt injection detection

High-velocity heuristics + on-demand classifier for sophisticated attacks. Two-layer protection with no perceptible latency.

Shadow AI

Shadow AI Discovery

Detects parallel use of ChatGPT, Gemini, and personal Claude.ai. The administrator sees where corporate policy is not being followed.

RAG

RAG anti-hallucination fidelity

Verifies that each response is supported by the retrieved context. Responses without corpus support are flagged before reaching the user.

Compliance

Complete audit trail

Every event — message, classification, blocking, model used — is recorded and exportable as CSV. Compliance documented per message.

Administrator panel

Full control for the administrator

Multi-tenant from day one, with isolation tested in production. The administrator sees everything, controls everything, without depending on the IT team for each configuration.

Isolation

Native multi-tenant

Row Level Security in Postgres — each organization is isolated in the database. Tested in production, not just documented on paper.

Financial

Granular billing per organization

Tokens consumed, cost in BRL, model used — per message, per user, per organization. Explainable billing for any internal client.

Access

RBAC without self-registration

Admin, member, and super-admin roles. No open registration — each user is added by the organization administrator. Real control over who uses the platform.

Automation

Autonomous agents

Cron jobs and Slack and Chatwoot webhooks. The agent executes scheduled tasks or event-triggered tasks, with a complete audit trail per execution.

Multi-provider

Multi-provider catalog with editable prices

Anthropic Claude, OpenAI, and Google Gemini in a single catalog. Administrators edit the prices shown to teams — useful for passing costs with margin to internal clients.

Why Tyna

Five reasons companies choose the platform

These are not marketing differentiators. They are architectural decisions with operational and financial consequences.

Cost under control by architecture

The automatic Haiku → Sonnet → Opus routing ensures each prompt pays exactly what it's worth. It's not a toggle — it's the default flow. Without this logic, 100% of prompts pay the price of the most expensive model.

Security built into the flow

Shield is not an additional feature or a compliance checkbox. It runs before each external transmission, silently for the user. It doesn't depend on training — it depends on architecture.

Multi-tenant ready to scale

Same instance, multiple clients, no risk of cross-leakage. Row Level Security implemented and tested — not just promised. Companies that resell AI to their clients use the same infrastructure.

Self-hosted on AWS

Data never leaves the environment controlled by Tyna. No user data traverses unmanaged infrastructure. For regulated sectors, this is not an option — it's a requirement.

Operational transparency

Per-message auditing, explainable billing, classification visible to the administrator. When the compliance team asks what happened to a piece of data, the answer is in the dashboard, not in a ticket for the engineering team.
